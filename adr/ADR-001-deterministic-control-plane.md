# ADR-001: Deterministic Control Plane Decoupling for Long-Horizon Agent Execution

**Status:** Accepted  
**Author:** Ken Huang, CISSP  
**Date:** 2026-10-26  
**Target Chapter / Harness Subsystem:** Chapter 01 (Deterministic Core Runtime) & Chapter 02 (Autonomy & Policy Gateways)

---

## 1. Context & Problem Statement
In long-horizon multi-agent workflows (such as autonomous software patching, cloud infrastructure remediation, or customer data pipelines), agents invoke external tools across multiple sequential steps. 

When tool execution boundaries are enforced solely through prompt engineering or secondary "LLM judge" evaluators, the security boundary inherits the probabilistic nature of language models. Attack vectors such as indirect prompt injection, multi-turn semantic drift, and jailbreaks frequently cause models to ignore negative prompt instructions and execute unauthorized destructive operations (e.g. arbitrary filesystem deletion or privilege escalation).

Furthermore, LLM-based safety checks incur significant token costs and variable latency (500ms to 3000ms per check), creating friction and race conditions in high-throughput agent fleets.

---

## 2. Decision Drivers
1. **Deterministic Security Boundary:** Access control decisions must be non-bypassable, regardless of the tokens generated by the foundation model.
2. **Sub-Millisecond Evaluation Overhead:** Gateway authorization must evaluate in less than 5 milliseconds to prevent latency degradation in multi-step chains.
3. **Auditability & Non-Repudiation:** Every authorization decision (`allow`, `deny`, `escalate`, `warn`, `rewrite`) must be logged into an append-only ledger with cryptographic evidence digests.
4. **Resilience to Model Swapping:** The control plane must maintain identical safety invariants even if the underlying model is upgraded, swapped, or fine-tuned.

---

## 3. Considered Architectural Options

### Option A: In-Context Alignment and LLM Safety Guardrail Agents
- **Description:** Rely on system prompts ("You are a secure assistant. Never run `rm -rf`") and route proposed tool calls to an LLM evaluator model before execution.
- **Pros:** Flexible, requires minimal software engineering, handles ambiguous natural language inputs.
- **Cons:** Probabilistic; susceptible to adversarial prompt injection; non-deterministic latency; significant token expenditure; cannot be formally certified for enterprise regulatory compliance.

### Option B: Deterministic Code Policy Gateway (Chosen Architecture)
- **Description:** Implement an out-of-band deterministic control plane in compiled/interpreted code (Python / Go) that intercepts all proposed tool invocations prior to execution. The gateway validates tool specifications, actor credentials, declared intent contracts, data classification tags, and capability budgets.
- **Pros:** 100% deterministic enforcement; sub-millisecond execution (< 1ms); mathematical guarantees against unauthorized tool dispatch; zero external model dependencies; non-bypassable by adversarial text.
- **Cons:** Requires explicit declaration of tool schemas, risk levels, and capability budgets.

---

## 4. Decision Outcome
We have chosen **Option B: Deterministic Code Policy Gateway**.

### Invariants Enforced:
1. **Zero Uncontracted Privileged Actions:** No tool call with risk level `IRREVERSIBLE_WRITE` or `PRIVILEGED_OPERATION` can execute without an active, non-expired `IntentContract` and an available `CapabilityBudget`.
2. **Hard Isolation:** The model layer only proposes tool calls; the control plane alone dispatches tool calls. The model has no direct network, file, or memory access outside the gateway.
3. **Immutable Decision Ledger:** Every evaluation produces a `PolicyDecision` object recorded in the execution trace.

---

## 5. Enterprise Implementation & Platform Mapping
- **Laboratory Primitive:** `harnesslab.core.ToolGateway` and `harnesslab.core.CapabilityBudget`
- **Enterprise Equivalent:** Open Policy Agent (OPA) with Rego policies deployed as an Envoy sidecar filter or AWS Bedrock Guardrails integrated into an API Gateway.
- **Deployment Strategy:** Deployed as a mandatory sidecar or ingress proxy in containerized agent environments (Kubernetes pods).
